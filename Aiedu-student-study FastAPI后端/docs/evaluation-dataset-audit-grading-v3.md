# 智能批阅 v3 评测集审核记录

## 审核结论

v3 在 v2 的 30 条答案上新增 30 条复杂 C 语言作答，总计 20 份提交、60 条答案。
所有样本已通过 Schema、分值边界、接受区间、类型分布和隐私检查，
可用于 Raw / Validate / Reflect 消融实验。

## 分布

| 类型 | 数量 |
| --- | ---: |
| 简答题 | 25 |
| 编程题 | 15 |
| 单选题 | 10 |
| 多选题 | 10 |
| 合计 | 60 |

其中 9 条标记为应人工复核。新增样本中包含长程序、多评分点部分得分、
结论正确但理由错误、看似合理但存在未定义行为，以及与参考代码不同但正确的实现。

## 金标准审核规则

1. `gold_score` 按 Rubric 分项计算，不使用模型自评分数。
2. `accepted_min` / `accepted_max` 只容纳合理的人工评分差异，必须包含金标准分数。
3. 程序题同时核对接口、主要逻辑、边界、终止性、溢出和资源管理。
4. 选择题对“结论错但理由接近”的作答保留部分分，不按全对/全错简化。
5. 涉及 ABI、实现定义、参考答案不唯一或题干约束不足的样本标记 `should_review=true`。

## Reflection 执行边界

v3 中每份批阅都固定执行一次、且最多一次 Reflection。下列风险不再决定
“是否复核”，只用于提示复核模型重点检查什么：

- 确定性校验发现缺题、总分、证据或边界错误；
- 模型低置信或主动要求人工复核；
- 较长的编程题作答；
- 含三个以上评分点的复杂部分得分答案。

提示词明确允许“第一次评分正确时保持原分”，
避免为了表现 Reflection 而强行改分。

## 局限

- 样本为项目内部合成并审核，不是独立双教师盲评。
- 第一版仍集中于 C 语言课程，不能直接代表所有学科的批阅效果。
- 是否保留 Reflection 只由正式实验的 MAE、接受区间准确率、修复和回归结果决定。
