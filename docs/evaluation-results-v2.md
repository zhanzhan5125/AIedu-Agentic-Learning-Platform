# AIedu RAG v2 正式评测结果

本页汇总 commit `aea1060936ecabaa6fccf55bae2f2fea5fc7fd40` 上的 RAG v2 正式结果。问题仍为 v1 的 40 条（32 条可回答、8 条不可回答），但结构化重切分后语料从 409 个有效块增至 597 个，并将金标准内容哈希重新映射和复核为 43 个相关证据。原始结果保存在 `Aiedu-student-study FastAPI后端/evals/baselines/v2`。

## 本轮修复

- 清除 PDF 重复页眉、页脚、页码、LinuxIDC 水印和目录噪声。
- 从 PDF 与未使用 Heading 样式的 DOCX 中恢复“第 X 章 / X.Y”层级。
- 同一 PDF 小节跨页保留约 80 tokens 重叠；生成答案时附加相邻完整句，但不改变评测所用的命中 chunk ID。
- 为 Dense、BM25 和 reranker 统一加入资料类型、标题、章节路径，并统一“第三章 / 第3章”。
- “课程要求/教学目标”按本项目语义识别为大纲查询；显式要求“大纲 + 教材”时均衡最终证据来源。
- Qdrant 写入改为 64 条一批，并在新批次全部成功后才清理过期 point ID，避免 3072 维向量超过服务端 32 MiB 请求限制以及失败前清空旧索引。

## v2 四路消融

| 模式 | Recall@5 | MRR@10 | nDCG@5 | Hit@1 | p95 延迟 |
|---|---:|---:|---:|---:|---:|
| BM25 | 0.6771 | 0.5956 | 0.5680 | 0.4062 | 380.6 ms |
| Dense | 0.9271 | 0.5854 | 0.6582 | 0.3125 | 1350.7 ms |
| Hybrid RRF | 0.8438 | 0.6977 | 0.7033 | 0.5000 | 1583.2 ms |
| Hybrid RRF + Rerank | 0.8906 | 0.7776 | 0.7814 | 0.6562 | 7395.4 ms |

在 v2 内部，rerank 相对 RRF 的 nDCG@5 增加 `0.0780`，Recall@5 增加 `0.0469`，但 nDCG 差值 95% bootstrap CI 为 `[-0.0014, 0.1682]`，仍跨过 0；CPU rerank 自身 warm p95 为 `5851.1 ms`，远超预设的 500 ms 上限。因此不推荐生产默认启用。

12 组端到端回答的盲化 Judge 结果为 11 平、1 次 Hybrid RRF 胜、0 次 rerank 胜。项目内逐组抽查同意该方向：rerank 改善了离线排序，但没有观察到最终回答质量收益。该检查不是独立教师双标。

## 结构修复是否有效

同一组章节问题上，结构修复后的提升很明显：

| 章节类模式 | v1 nDCG@5 | v2 nDCG@5 | 变化 |
|---|---:|---:|---:|
| BM25 | 0.3914 | 0.6414 | +0.2500 |
| Dense | 0.5811 | 0.7279 | +0.1468 |
| Hybrid RRF | 0.5419 | 0.7827 | +0.2408 |
| Hybrid + Rerank | 0.5474 | 0.9288 | +0.3814 |

这说明标题恢复、章节别名和结构元数据解决了原先最明确的章节定位缺陷。整体指标并非全部上升：v2 的金标准更严格（40 增至 43 个证据），语料也增加了 46%，纯 RRF 的整体 Recall@5 从 0.9219 降至 0.8438。不能把 v1/v2 当作只改变一个变量的严格消融，也不能宣称所有查询都变准。

## 当前取舍与简历表述

生产默认使用 Dense + BM25 + RRF；本地 CPU reranker 默认关闭，但保留显式评测能力。推荐的保守表述：

> 针对 PDF/DOCX 课程资料实现结构恢复、跨页重叠、章节别名与来源约束；在 40 条人工复核问题上，章节定位的 Hybrid nDCG@5 从 0.5419 提升至 0.7827。Cross-Encoder 将 v2 整体 nDCG@5 从 0.7033 提升至 0.7814，但 CPU warm p95 增加 5.85 秒且端到端未获胜，因此依据预设门槛不默认启用。

## 限制

- v1/v2 语料粒度和证据数不同，整体差值只能作为迁移前后观察，不能视为严格单变量实验。
- 数据只覆盖一门 C 语言课程，且尚无独立教师双标。
- Qdrant 客户端 1.15.1 对服务端 1.19.1 有兼容性警告；本轮查询成功，但版本应统一后再做最终延迟基准。
